### [P2] Corp-only map at 80x24 clips the per-territory actions and the ledger

- Seed: 555002
- Screen: `New Game` → `Corp` → Ironclad Dynamics → `CorpMapScreen` (`corp_only`)
- Steps: boot at `run_test(size=(80, 24))`; start a corp run; inspect the map regions.
- Expected: the per-territory corp actions panel and the `#corp_info` ledger are
  reachable at the minimum size.
- Actual: `#map_corp_actions_scroll` is laid out at `y=22` (height 5) but the footer
  is at row 23; `#map_corp_actions` is `y=23`, height **1** — only a sliver is
  visible. `#corp_info` is at `y=27`, entirely below the 24-row viewport, in both
  map mode and the Corp tab.
- Workaround: the **Corp tab is still usable** — `#activities` at `y=8` (height 22)
  lists Expand/Develop/Survey/Train rows, and Tab → `cat_corp` → Enter reaches it.
  So this is P2, not a dead end.
- Evidence:
  ```
  #top_bar                 Region(x=0, y=1,  width=80, height=7)
  #map_scroll              Region(x=0, y=8,  width=80, height=10)
  #territory_summary       Region(x=0, y=18, width=80, height=4)
  #map_corp_actions_scroll Region(x=0, y=22, width=80, height=5)
  #map_corp_actions        Region(x=0, y=23, width=80, height=1)
  #corp_info               Region(x=0, y=27, width=80, height=6)
  ```
- Repro: yes, 2/2.
- Note: the runner map was fixed in the last commit; this corp-only branch uses the
  same `main_panel` but adds the auto-height `#corp_info` ledger, which is what
  overflows here.

### [P3] Research Facility line hides the facility's own RP/day

- Seed: 555002
- Steps: run the corp from day 1 to day 10 with **0 scientists**; read the
  `#corp_info` line and the RP total each day.
- Expected: the facility line names its own tier income (the code does
  `total += facility.research_tier` — tier 1 is 1rp/day even with nobody staffing
  it), so the player can tell where the RP is coming from.
- Actual: the line reads
  `Research Facility: tier 1, 0/1 scientists at work (1rp/scientist), 0/2 assistants…`
  while RP rises 0 → 1 (day 2) → 6 (day 3) → 7 (day 10). With 0 scientists the
  only visible rate is 1rp per scientist, so the 1rp/day looks unexplained.
- Evidence: `research_points` 0.0 → 1.0 → 6.0 → 7.0 with `scientists = 0`.
- Repro: yes, 1/1. This is a clarity issue; the behaviour itself is intended
  (`collect_research`'s docstring: “its tier directly”).
