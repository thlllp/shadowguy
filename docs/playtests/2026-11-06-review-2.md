## Verdict

The two new reports are the strongest Allie output so far. They are precise,
reproducible, and — critically — they **catch a real gap in the 76f58e7 fix** and a
**new invisible-focus bug** that the suite does not cover. I reproduced both of the
corp claims at 80x24.

## New findings — verified

### [P2] Corp ledger still clipped and unscrollable at 80x24

Confirmed. At `run_test(80, 24)`, after an expand and a few rests:

```
#corp_info  Region(x=0, y=20, width=80, height=3)
virtual_size Size(width=80, height=3)   can_focus False
content lines: 4
rendered rows 20-22: faction line (wrapped) + Territories line
```

`Logistics: …` and `Research Facility: …` never render. `virtual_size` equals the
widget size, so `overflow-y: auto` does not create a scrollable overflow; the Static
is not focusable and no Tab target reaches it. At 100x40 all four lines render.

The report is also right that the regression test is weak: it asserts
`"Research Facility" in #corp_info.content` (the source string) rather than the
rendered screen. **76f58e7 put the ledger on screen but did not make its content
reachable at the documented 80x24 minimum.**

### [P2] Corp tab's off-screen panels are focusable and spend resources

Confirmed. At 80x24 in the Corp tab:

```
#activities          y=8   h=18
#academy_panel       y=28  h=9
#research_panel      y=37  h=6
#surveillance_panel  y=43  h=3
#corp_info           y=26  h=2
```

`#academy_list` is at `y=31` (off-screen), yet it takes focus and selecting
`academy_grant` fired: cash 2300→2050, RP 2→4, AP 2→1. The visible screen never
shows “Research grant”. This is worse than a layout blemish — it is an invisible
control that spends resources. The report's before/after tuple is exactly right.

### [P2] Saving mid-fight and loading discards the encounter

Plausible and consistent with the code: `app.save_run()` stores character/map/fixers
but no fight state, and `load_state` always reopens `CorpMapScreen`. I did not
replay this one, but the report's evidence (`save bundle has no combat key`) matches
the implementation. Treat as a real design gap (save-scum out of a losing fight),
not a crash.

### [P3] Rest has no keyboard path

Real on both maps. `#rest_button.can_focus = False` and no Rest binding exists; Tab
never reaches it. The report calls it P3 on both. I would **upgrade the corp case to
P2**: on a corp-only run Rest is the only way to advance the day from the map, so a
keyboard-only corp player cannot advance time at all.

### [P3] Out-of-district Job/Legwork row silently no-ops

Real. `on_list_view_selected` returns at `if not self._on_site(job.scene): return`
with no notify. The row label says “travel to …”, then nothing happens. A refusal
toast is the right fix.

## Report-quality assessment

**Strengths of the new reports**
- Exact regions and `virtual_size` for layout claims; a focus/contents check for the
  invisible panel; before/after resource tuples.
- Correctly identifies a weak regression test and explains *why* it passes.
- Distinguishes balance (logistics cost, action-list flood, passive rivals) from
  defects, and quantifies it (253 `Gather intel` rows; 120 rival days; first attack
  day 87).
- “Not reached” is explicit and session-scoped.

**Weaknesses**
- The mid-fight save finding could state the design options more concretely (refuse
  save during a fight vs persist the encounter vs warn); it does list them, so this
  is minor.
- The runner report's “Not reached: … the 80x24 runner map” is session-local; the
  80x24 runner map *was* covered on seeds 424242/90210. Cumulative readers could
  misread it as a global gap.
- Reports still live only in `/tmp`; the durable record is the commit and the
  transcript.

## Recommendations (in priority order)

1. **Fix the corp ledger properly.** Either give `#corp_info` a real height
   (`min-height: 4` at 80x24 plus a compact/one-line territory list), or make it a
   focusable/scrollable `Static`/`ScrollableContainer`. The test must assert the
   **rendered** text (`app.screen._compositor.render_strips()` or equivalent)
   contains `Logistics:` and `Research Facility:`, not `.content`.
2. **Fix the Corp tab overflow.** Cap `#activities` (`height: 1fr; max-height: …`)
   and give the panels a scroll container, or skip focus for widgets whose region
   is outside the screen. Add a test that no focusable widget on the Corp tab has
   `region.y >= terminal_height` at 80x24.
3. **Add a Rest key** (e.g. `R`) on both map screens, or make the button focusable.
   On corp runs this is the only day-advance path.
4. **Decide mid-fight saves.** Refuse Save while a fight screen is on the stack, or
   persist the encounter; document whichever.
5. **Notify on out-of-district job/legwork selection** (“You need to be on site”).
6. **Balance notes to DESIGN.md:** Logistics Optimization's 200rp first level versus
   the 50rp tech tree; the 253-row `Gather intel` flood; rival attacks not reaching
   the player's ground by day 120.
