# Review of Allie's playtest output

Scope: the sessions on seeds **424242, 777001, 161803, 90210, 555001/555002,
555003/555004**, the resulting fix commit **2c3fd19**, and the three reports
still on disk (`2026-11-06-postfix-90210.md`, `2026-11-06-runs-555001-555002.md`,
`2026-11-06-coverage.md`). Earlier reports lived in `/tmp` and were wiped; only
their findings survive in the transcript and the commit.

## Overall

Allie's output was **useful**: it produced seven concrete fixes, three regression
tests, and a real coverage map of the game's surfaces. Its best habit is
reproducibility — every finding carries a seed, screen, steps, evidence and a
repro count, and the defect/balance split is respected.

Its main weaknesses are **early overconfidence** (two provisional findings were
wrong and had to be retracted), **fuzzy severity/acceptance criteria** (the
80x24 P1 ended as a partial fix), and **ephemeral reporting** (the reports were
written to `/tmp`, not the repo).

## Findings Allie got wrong or overstated

- **“Settings broken on every run_test() boot”** — wrong framing. It was a layout
  collapse, not a settings/config problem. Corrected in the next pass.
- **“`ListView.index` is `None` on entering shops/fixers”** — false. `_replace_items`
  sets index 0; the only real issue was focus landing on a Collapsible title.
  Dropped.
- **“Free lodging at 0eb”** — real behaviour, but not a defect. Correctly demoted
  to balance/feel (`rest()` charges `min(cost, cash)`).
- **“An enemy acts 3× per player turn”** — intended scheduler behaviour (“a quick
  one can act twice”); correctly excluded.
- **P1 for the map at 80x24** — arguable. The repo only *asserts* 80x24 for
  creation; the README never states a minimum. The fix improved the screen but
  did not make it comfortable, so the original severity implied more than was
  delivered. A P1 that lands as a partial fix is really a P1 with an undefined
  acceptance criterion.
- **“Corp defeat not reachable”** — the 60-day soak was too short; the follow-up
  reached it on day 104. The first report should have said “not reached in 60
  days”, not implied unreachable.

## Report quality

**Strengths**
- Every entry is replayable: seed, screen path, numbered steps, expected/actual,
  trimmed evidence, repro count.
- Defects and balance observations are separated; “luck is not a bug” is applied.
- Corrections were disclosed rather than silently rewritten.
- Coverage reports state what was *not* reached, which is rare and useful.

**Weaknesses**
- Two premature findings; the first report mixed a driver bug (wrong list id)
  with a game bug. A quick replay before writing would have caught both.
- Severity is inconsistently applied (P1 for a partially-fixable layout; P3 for
  a misleading number).
- Reports are written to `/tmp/opencode/allie/` and are lost when the machine or
  session is cleaned. The durable output is only the commit and this transcript.
- The Test menu was used for burglary/fishing/bodyguard; this is disclosed, but
  it means those surfaces were not driven through the player-facing route.
- Some probes are brittle harness code (focus by Tab count, selector ids); they
  are fine for a session but not reusable as a suite.
- No issue-tracker entries were filed; nothing links the findings to the commit
  except this conversation.

## Recommendations

1. **Fix the open P2** (corp-only 80x24): give `#corp_info` `height: 1fr;
   max-height: 6; min-height: 2; overflow-y: auto`, or hide it at short heights.
   Add a regression test asserting `#map_corp_actions`/`#corp_info` are on-screen
   at 80x24.
2. **Decide the minimum terminal size** and put it in the README. Either finish
   the responsive layout or state 100x30+.
3. **Persist reports**: move them to `docs/playtests/` (or attach to issues) and
   link each finding to its commit/test.
4. **Add an RNG hook** for forcing a critical failure (or accept the security
   “blown” branch as untested and say so in the manual).
5. Keep the report format; it is the strongest part of Allie's output.
